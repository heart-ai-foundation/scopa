## Why this exists

S14 closed process, terminal, installed-identity, and evidence custody before
additional provider traffic. The current Claude proof still covers only
allowed work, scope denial, false-green refusal, and cold restart. It does not
yet establish bounded behavior for live capability drift, provider refusal,
rate pressure, timeout, ignored termination, early EOF, malformed events,
capture exhaustion, budget stop, or repeated-session residue.

## Next objective

Build and execute a bounded Claude Code headless edge campaign against the
exact installed SCOPA candidate. Freeze an explicit per-run account, network,
model, tool, time, turn, token/cost, evidence-retention, and cleanup policy
before any provider call. Prove every live scenario locally with deterministic
fault controls first, then run only the approved live subset and remediate only
reproduced provider-boundary defects.

Activation of this protocol does not itself start provider traffic. The
provider gate remains closed until the complete run policy is materialized and
validated.

## Provider execution gate

Before the first real Claude request, commit a closed policy that names:

- the authenticated account boundary without credential material;
- the only allowed provider network destination class;
- the requested Claude model alias and honest non-snapshot limitation;
- the exact SCOPA MCP tool inventory and denial of other mutation routes;
- maximum provider invocations, turns, wall time, input/output capture, token
  or CLI usage bounds, and maximum USD spend;
- disposable repository and prohibited data classes;
- private raw-evidence retention duration, maximum bytes, mode, and deletion
  procedure;
- cleanup proof and immediate stop conditions.

The runner must refuse provider execution when any field is missing, when the
policy digest differs, or when the client/capability probe drifts. A real run
must not be a default `npm test` or hosted-CI dependency.
