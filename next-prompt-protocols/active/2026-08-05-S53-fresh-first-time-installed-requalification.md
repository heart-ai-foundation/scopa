# S53 — Fresh First-Time Installed Requalification

**Class:** `arc`
**Module:** `release-readiness`
**Crosses:** [`adoption-experience`, `enforcement`]
**Advances contracts:** [`FH2`]
**Compound:** false
**Status:** active

## Why this exists

S52 changed the exact first-time behavior that a fresh installed-package agent
found materially incomplete. Source and accumulated tests are clean, but the
loop closes only when a different unfamiliar consumer can use the packed tool
from its public-facing entry without rediscovering a critical, high, or medium
product defect.

## Next objective

Give one fresh agent the exact locally packed S52 candidate. Require an offline
install with lifecycle scripts disabled into an isolated tool root, then have
the agent use only package-facing documentation and output to exercise cold
first insight, assistant preview/install, begin/check/view/map, tracked and
untracked hostility, evidence export, badge, privacy, recovery, uninstall, and
cleanup. Retain its commands, exact candidate identity, findings, and verdict.

## Anti-ceremony gate

- Classification: installed-product validation.
- Executable change: one fresh consumer executes the exact packed runtime.
- New uncertainty reduced: whether the repaired first-time journey is legible
  and truthful without implementation context.
- This is the only fresh requalification. Do not add review-of-review,
  approval, digest, or status-only slices.

## Descriptor rung check

Executable unlock: the fresh agent installs and operates exact packed bytes in
an isolated repository. Its report must include commands, observed behavior,
cleanup, and a severity-ranked verdict; a status-only review cannot satisfy
FH2.

## Productivity mix

- Runtime behavior: 0%
- Contract/test execution: 85%
- Metadata/evidence: 15%

This is the single validation slice immediately after runtime-dominant S52. It
executes the installed product and is not a descriptor ladder.

## Acceptance

- Candidate identity is recorded before use and every executed package path
  resolves under the isolated installed root.
- Install is local/offline with lifecycle scripts disabled; no source module,
  provider, model, experiment, telemetry, network, or customer system is used.
- The agent relies only on public/package-facing material and independently
  verifies the repaired completion, untracked-observation, terminal-recovery,
  continuation, export-boundary, badge, privacy, and cleanup behavior.
- No critical, high, or medium product finding remains.
- Temporary install and fixture roots are removed after the report is retained.

## Evidence

Retain the fresh-agent report, exact tarball identity, installed command log,
privacy and cleanup observations, and final severity verdict under
`evidence/S53/`, with concise execution notes under `notes/S53/` and
`runs/S53/`.

## Non-goals

- No release, npm publication, GitHub Release, tag, merge, announcement,
  repository setting, deployment, or external-system action.
- No provider/model call, production-live run, experiment, customer repository,
  customer data, hosted service, or network dependency.
- No transfer of public `0.4.0` assurance to the changed candidate and no claim
  that this pass authorizes release.
- No new review layer after a clean verdict.

## Stop condition

Stop and return to bounded implementation on a reproducible critical, high, or
medium product finding, false clean, missing untracked contact, privacy leak,
cleanup failure, installed/source substitution, provider/network intent, or
any release, publication, merge, announcement, or external-system action.
